CLAUDE.md

Этот файл — контекст для Claude Code при работе над проектом. Читай его перед началом любой задачи в этом репозитории.

О проекте

Платформа для сообщества, которое сохраняет нематериальное культурное наследие (обряды, музыку, ремёсла, язык, устные истории) до того, как оно исчезнет вместе с носителями.

Проблема, которую решает продукт: у людей есть желание сохранять традиции, но нет инструмента, который бы одновременно фиксировал материалы, помогал находить единомышленников и превращал абстрактную идею в конкретные маленькие задачи. Абстрактные призывы не работают — людям нужен конкретный повод, роль и видимый результат.

Полное ТЗ: см. ТЗ_сообщество_наследие.md в корне репозитория — это источник истины по требованиям. Если этот CLAUDE.md и ТЗ расходятся, следовать ТЗ и предложить обновить этот файл.

Целевая аудитория (важно для UX-решений)
Носители традиций — пожилые люди, мастера. Часто не технически подкованы: интерфейс для них должен быть максимально простым (крупные кнопки, минимум шагов, желательно с помощью «проводника»-помощника рядом).
Помощники — студенты, учителя, работники культурных учреждений. Основные активные пользователи интерфейса.
Молодёжь/диаспора — потребители контента, потенциальные волонтёры.

Любое проектное решение проверяй вопросом: не усложняет ли это жизнь носителю традиции, который впервые видит компьютер/приложение.

Три модуля MVP
1. Архив-запись

Сущность Record: файл (аудио/видео/фото) или текст + carrier_name (имя носителя, обязательно и видимо) + type (enum: song / ritual / craft / oral_history) + location, date_recorded. Ключевое требование: авторство носителя всегда отображается рядом с материалом, никогда не обезличивается.

2. Карта людей

Сущность Person: name, skills_or_knowledge (свободный текст или теги), role (carrier / helper), опционально location. Нужен фильтр/поиск по навыку и роли. Личные сообщения между участниками — минимально: достаточно контакта (телефон/telegram) в профиле на старте, полноценный чат не обязателен для MVP.

3. Лента маленьких дел

Сущность Task: title, description, deadline, status (open / in_progress / done), responders (список откликнувшихся), result_link (ссылка на Record после выполнения). Задачи должны формулироваться конкретно и с ограниченным сроком (принцип «маленькое дело», не абстрактная миссия) — при генерации примеров/сидов данных придерживайся этого стиля.

Принципы вовлечения → как это влияет на код и контент
Тексты в UI (плейсхолдеры, примеры задач) должны быть конкретными и человечными («записать колыбельную у бабушки Зайнаб до 30 сентября»), не абстрактными («сохранить культуру»).
Прогресс должен быть видимым: счётчики выполненных задач, число откликнувшихся — это не второстепенный UI-элемент, а часть механики вовлечения.
Платформа дополняет офлайн-встречи, а не заменяет — не проектировать функции, которые изолируют пользователей друг от друга (например, не приоритизировать анонимность).
Стек и архитектура

Зафиксирован:

SvelteKit 2 / Svelte 5 с SSR — самый лёгкий бандл и готовый HTML до загрузки JS (слабый интернет в Таджикистане). Формы работают и без JS.
Supabase — Postgres, хранилище медиа, вход по одноразовой ссылке на почту, права через RLS. Бесплатный тариф, поддержка одним человеком, регион Frankfurt.
Cloudflare Pages — бесплатный хостинг с CDN. В svelte.config.js стоит adapter-auto, а не adapter-cloudflare: последний в dev-режиме поднимает эмуляцию workerd, которая на Windows роняет каждый запрос ошибкой write EOF. На хостинге adapter-auto сам подставит cloudflare-адаптер.

Данные страниц грузятся на сервере (+page.server.ts) через locals.supabase; браузерный клиент (src/lib/supabase.ts) нужен только для входа/выхода. Схема и права — supabase/migrations/0001_init.sql. Подробности и инструкции по запуску — в README.md.

Решения, которые не менять без обсуждения: имя носителя NOT NULL и на карточке; срок задачи обязателен; фильтры через query-параметры, а не состояние в JS; изображения сжимаются в браузере; медиа с preload="none".

Вход и роли

Носители традиций не регистрируются: носитель — это не аккаунт, а имя рядом с материалом (records.carrier_name). Регистрируется помощник, который приходит к носителю с телефоном и заводит за него запись и анкету. Просмотр открыт всем без входа; вход нужен только чтобы что-то добавить.

Языки

Русский, таджикский и английский — все строки в src/lib/i18n/{ru,tg,en}.json. Новый текст в интерфейсе добавляй сразу во все три файла. Таджикские переводы пока не вычитаны носителем языка — при правках не считай их эталоном.

Этап проекта

Каркас приложения написан и запускается: npm run check и npm run build проходят без ошибок, dev-сервер отдаёт все страницы на обоих языках. База ещё не подключена — в .env заглушки вместо ключей Supabase, поэтому ленты пустые. Ближайшие шаги — создать проект в Supabase, накатить supabase/migrations/0001_init.sql, вписать ключи в .env и проверить сквозной сценарий: создать дело → откликнуться → добавить запись → отметить дело выполненным.

Параллельно с приложением идёт набор первого ядра участников (ориентир ТЗ — 10–15 человек). При работе над кодом уточняй у пользователя, какой этап актуален, если это не очевидно из репозитория.

Общие правила работы над проектом
Пиши интерфейсные тексты на русском (и/или таджикском, если попросят) — основная аудитория не англоязычная.
Не добавляй функциональность вне трёх модулей MVP без явного запроса — проект должен оставаться простым для аудитории, которая не является технической.
При сомнениях в приоритете — сверяйся с принципом «маленькое конкретное дело» и с простотой для носителей традиций, а не с технической элегантностью.
